# Invigilation Duty System — Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working Django system in which the exam office imports departments, faculty and an exam schedule, runs a fair clash-free allocation, reviews and edits the draft, publishes it, and exports rosters as PDF/Excel.

**Architecture:** One Django project with focused apps (`accounts`, `faculty`, `exams`, `duties`, `audit`, `allocation`, `reports`). The allocation engine is a pure-Python module (`allocation/engine.py`) with no database access; a thin service layer (`allocation/services.py`, `duties/services.py`) loads data, calls it, and saves results. Server-rendered templates with plain POST forms; Django Admin for back-office data entry.

**Tech Stack:** Python 3.13, Django 5.2 LTS, SQLite for local development / PostgreSQL in production (via `DATABASE_URL`), openpyxl (Excel), reportlab (PDF), pytest + pytest-django.

**Spec:** `docs/superpowers/specs/2026-10-20-invigilation-duty-system-design.md`

## Global Constraints

- Phase 1 scope only (spec §12): models, Django Admin, Excel imports, PeriodSettings, allocation engine + draft review + manual edit, publish, PDF/Excel rosters. No faculty login pages, unavailability UI, emails, swaps, replacements, attendance UI (Phases 2–3). Unavailability is entered through Django Admin in Phase 1.
- All invigilators are equal — no chief/regular roles.
- No carry-over of duty counts between exam periods.
- PeriodSettings defaults: `max_duties_per_faculty=8`, `max_duties_per_day=2`, `students_per_invigilator=30`, `min_invigilators_per_room=2`, `avoid_back_to_back=True`, `exclude_course_teacher=True`.
- `invigilators_required = max(min_invigilators_per_room, ceil(student_count / students_per_invigilator))`.
- Only `approved` Unavailability blocks allocation.
- Inactive (`is_active=False`) and exempt (`is_exempt=True`) faculty are never allocated.
- Imports are all-or-nothing: validate every row, report every error as `"Row N: <message>"` (header is row 1), save nothing if any error.
- Allocation never raises on shortages; it reports unfilled seats with reasons.
- AuditLog is append-only: no role, including Admin and superuser, can change or delete entries through the application.
- Every view in Phase 1 requires the `ADMIN` role (superusers pass).
- No Docker or PostgreSQL is installed locally: development and tests use SQLite; code must not use SQLite- or PostgreSQL-specific features except partial unique constraints (supported by both).
- Commands are run from the project root on Windows: `.venv\Scripts\python ...`.

## Review Focus

1. **Real-world spreadsheets** — Excel date/time cells arriving as `datetime`/`time` objects, header case and spacing differences, trailing blank rows, stray whitespace. Expected: imported as if typed cleanly. *(tests in Task 9)*
2. **Re-running after manual edits** — the manager hand-assigns someone, then clicks "Run allocation" again. Expected: manual duties survive and count toward that person's caps. *(test in Task 7)*
3. **Changing data after a draft exists** — a faculty member becomes exempt, or the schedule is re-imported, after duties exist. Expected: re-run drops the exempt person's auto duties; schedule import is refused while duties exist, with a message to clear the draft first. *(tests in Tasks 7 and 9)*
4. **Acting on a published period** — running allocation, clearing, editing, importing or publishing again after publish. Expected: blocked with the message from `PeriodLockedError`. *(tests in Tasks 7, 8, 11)*
5. **Two duties in one slot via manual edit** — the manager adds someone already sitting in another room at the same time. Expected: blocked with "Already assigned in this time slot". *(test in Task 8)*

```python
@dataclass(frozen=True)
class Slot:   id: int; date: date; order: int        # order = 0-based index among slots of the same date, by start_time
@dataclass(frozen=True)
class Room:   id: int; slot_id: int; needed: int; course_teacher_ids: frozenset[int] = frozenset()
@dataclass(frozen=True)
class Person: id: int; department_id: int; cap: int
@dataclass(frozen=True)
class Rules:  max_per_day: int; avoid_back_to_back: bool; exclude_course_teacher: bool
@dataclass(frozen=True)
class EngineInput:
    slots: list[Slot]; rooms: list[Room]; people: list[Person]; rules: Rules
    unavailable_days: frozenset[tuple[int, date]] = frozenset()   # (person_id, date)
    unavailable_slots: frozenset[tuple[int, int]] = frozenset()   # (person_id, slot_id)
    fixed: tuple[tuple[int, int], ...] = ()                        # existing (person_id, room_id) duties, kept as-is
@dataclass(frozen=True)
class Unfilled: room_id: int; count: int; reason: str
@dataclass(frozen=True)
class FairnessStats: min: int; max: int; avg: float
@dataclass(frozen=True)
class AllocationResult:
    assignments: list[tuple[int, int]]   # NEW (person_id, room_id) only
    unfilled: list[Unfilled]; stats: FairnessStats; soft_violations: int; seed: int

class AllocationState:
    def __init__(self, data: EngineInput) -> None   # indexes input and applies `fixed`
    def check(self, person_id: int, room_id: int) -> tuple[list[str], list[str]]   # (hard errors, soft warnings)
    def assign(self, person_id: int, room_id: int) -> None
    def count(self, person_id: int) -> int
    def remaining(self, room_id: int) -> int        # needed minus assigned, floor 0

def fairness_stats(counts: Iterable[int]) -> FairnessStats   # empty → FairnessStats(0, 0, 0.0); avg rounded to 2 dp
def allocate(data: EngineInput, seed: int) -> AllocationResult
```

Exact messages (used by UI and tests):
- Hard: `"Already assigned in this time slot"`, `"Marked unavailable for this date or slot"`, `"Reached period cap ({cap})"`, `"Reached daily limit ({max_per_day})"`.
- Soft (only when the corresponding rule is on): `"Back-to-back with another duty"` (same date, `|order difference| == 1`), `"Teaches this course"`.

In this task `allocate` fills rooms in input order, choosing for each seat the candidate with no hard errors and the fewest duties (ties: lowest person id). Unfilled seats get reason `"No eligible faculty"` for now (Task 6 refines). Task 6 replaces ordering/ranking without changing signatures.

### Task 6: Allocation engine — hardest-first, soft rules, determinism, reasons, capacity check

**Files:**
- Modify: `allocation/engine.py`
- Test: `allocation/tests/test_engine_ranking.py`

**Interfaces:**
- Consumes: Task 5 types.
- Produces:

```python
@dataclass(frozen=True)
class CapacityReport:
    seats_needed: int; capacity: int; ok: bool
    slot_shortages: list[tuple[int, int, int]]   # (slot_id, seats_needed_in_slot, people_available_in_slot)

def capacity_check(data: EngineInput) -> CapacityReport
```
  - `seats_needed` = Σ `remaining(room)` after fixed; `capacity` = Σ `max(0, cap − fixed_count)`; `ok = seats_needed <= capacity`.
  - A slot is short when its remaining seats > people not unavailable for it (day or slot) and not already fixed in it.

`allocate` algorithm (replaces Task 5's):
1. Seat order: slots sorted by `remaining_seats_in_slot / available_people_in_slot` descending (0 available → infinite), ties by `(date, order)`; rooms within a slot by id.
2. Tie-break order: `random.Random(seed).shuffle` of person ids, done once; a person's index in that list is their tie-break value.
3. Candidate ranking key: `(number_of_soft_warnings, count(person), 1 if person's department already has someone in this room else 0, tie_break_index)`; lowest wins. Only candidates with no hard errors.
4. `soft_violations` in the result = total soft warnings of the chosen assignments.
5. Unfilled reason for a room: among people not already in that slot, classify each by the first failing check in order unavailable → period cap → daily limit. If no such people: `"All faculty are already assigned in this time slot"`. If all share one class: `"All remaining faculty are unavailable"` / `"All remaining faculty have reached their period cap"` / `"All remaining faculty have reached their daily limit"`. Otherwise: `"No eligible faculty: {a} unavailable, {b} at period cap, {c} at daily limit"`.
